# Recipe Explorer

A Flutter app for browsing recipes from [TheMealDB](https://www.themealdb.com/api.php). You sign in, pick a category or search by name, and tap a recipe to see its ingredients, instructions and links.

Built for COMP 4970 (Mobile Applications Development). Module 4 was the REST API part, and Module 5 (Cloud Data Synchronization) added Firebase email/password login in front of it.

## What it does

- Sign up and sign in with email and password through Firebase Auth. You can't get to the recipes without being signed in, and there's a log out button (with a confirm dialog) in the app bar
- The forms check for empty fields, a missing @, short passwords and mismatched passwords, and Firebase errors like a wrong password or a taken email show up as plain messages
- A row of category chips loaded from TheMealDB (it opens on Beef)
- A search bar that searches meal names. It waits 350 ms after you stop typing before sending the request
- A two-column grid of recipe cards with photos
- A detail screen with the photo, category and cuisine tags, the ingredient list with little ingredient pictures, the instructions, and buttons for the YouTube video and original recipe when TheMealDB has them
- Loading spinners, an error view with a retry button if a request fails, and an empty message when a search finds nothing

## How it works

`lib/services/meal_api.dart` wraps the four TheMealDB endpoints the app uses:

| Endpoint | Used for |
| --- | --- |
| `categories.php` | the category chips |
| `filter.php?c=<category>` | meals in a category |
| `search.php?s=<query>` | searching by name |
| `lookup.php?i=<id>` | the full recipe on the detail screen |

Every request has a 15 second timeout, and network failures, non-200 responses and bad JSON all get turned into a `MealApiException` with a readable message so the screens can show the retry view instead of crashing. Images load through `cached_network_image` with a placeholder and an error icon, so one broken thumbnail doesn't mess up the grid.

For login, `lib/widgets/auth_gate.dart` listens to `FirebaseAuth.authStateChanges()` and shows either the login screen or the home screen. Signing in or out swaps the screen automatically. `lib/services/auth_service.dart` is a thin wrapper around `FirebaseAuth` plus a function that maps Firebase error codes to friendlier text.

```
lib/
  main.dart               Firebase init, then AuthGate
  firebase_options.dart   generated by flutterfire configure
  models/                 meal_category, meal_summary, meal_detail
  services/               meal_api.dart, auth_service.dart
  screens/                home, detail, login, sign_up
  widgets/                meal_card, status_views, auth_gate, auth_text_field
  theme/                  app_theme.dart (Material 3, orange seed color)
```

## Running it

You need the Flutter SDK (Dart 3.3.4 or newer).

The committed `lib/firebase_options.dart` only has a web config, so as-is the app only starts in Chrome. On Android, iOS or desktop it throws an "options have not been configured" error at startup. To run it on another platform, or against your own Firebase project:

1. Create a project in the [Firebase console](https://console.firebase.google.com) and turn on Email/Password under Authentication > Sign-in method.
2. Install the CLI tools and log in:
   ```bash
   npm install -g firebase-tools
   dart pub global activate flutterfire_cli
   firebase login
   ```
3. Run `flutterfire configure` in the project folder. It rewrites `lib/firebase_options.dart` for the platforms you pick.

Then:

```bash
flutter pub get
flutter run -d chrome
```

The tests only cover the JSON parsing in the meal models (missing fields, joining ingredients with their measurements, the ingredient image URL), so they don't need Firebase or a network:

```bash
flutter test
```
